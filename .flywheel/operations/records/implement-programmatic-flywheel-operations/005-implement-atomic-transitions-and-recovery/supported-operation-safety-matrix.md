# Supported Operation Safety Matrix

| Operation | Tested guarantees | Retry behavior | Recovery behavior | Unsupported cases |
|---|---|---|---|---|
| `start-execution` | Validates the complete proposed goal, execution, and state mutation before persistence; rejects stale source revisions; prevents duplicate execution IDs and concurrent active executions. | Retry after validation or stale-source rejection is safe after the caller refreshes canonical inputs. Repeating a completed request is rejected explicitly rather than creating a duplicate execution. | A persistence interruption restores modified canonical files and removes newly created partial artifacts and temporary files. | Mission design, goal authoring, approval creation, and execution completion remain governed AI work. |
| `advance-lifecycle` | Validates execution and state together; enforces lifecycle order; rejects malformed or stale artifacts; supports an expected-stage guard for replay detection. | Callers should provide `--expected-stage`. A retry succeeds when the stage remains unchanged; a replay after a successful transition is rejected with the actual stage. | A persistence interruption restores execution and state to their prior bytes and removes temporary files. | Completing `reuse`, closing executions, approval decisions, and unsupported lifecycle shapes remain governed AI work. |
| Shared mutation boundary | Locks the repository, checks retained SHA-256 revisions, validates a complete shadow repository, replaces canonical files, and rolls back written files on exceptions. | Validation and stale-revision rejections make no canonical changes. Interrupted commits may be retried against the restored source revisions. | Backups restore every path touched before the interruption; newly created files and temporary files are removed. | Guarantees apply only to callers using this boundary and only to the tested YAML mutation paths. |

These guarantees do not claim complete programmatic operation of the AI Flywheel.
